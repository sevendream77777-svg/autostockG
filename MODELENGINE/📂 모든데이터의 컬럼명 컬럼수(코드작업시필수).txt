기술적 지표 (AI 학습용 핵심 피처):

이동평균: SMA_5, SMA_20, SMA_40, SMA_60, SMA_90, SMA_120

거래량 이평: VOL_SMA_20

추세/모멘텀: RSI_14, MOM_10 (Momentum), ROC_20 (Rate of Change)

MACD: MACD_12_26 (MACD선), MACD_SIGNAL_9 (시그널선)

스토캐스틱: STOCH_K, STOCH_D

기타: CCI_20 (Commodity Channel Index), ALPHA_SMA_20 (시장 대비 초과 수익률)

🧠 3. HOJ DB & ENGINE (학습 및 예측 단계)
최종적으로 AI 엔진이 읽어들이는 형태입니다.

사용 코드: daily_recommender.py (또는 train_engine_unified.py)

입력 컬럼 (15개 핵심 피처): 모델은 위의 수많은 피처 중 가장 중요한 15개를 골라서 사용합니다. Change (등락률), SMA_5, SMA_20, SMA_60, VOL_SMA_20, MOM_10, ROC_20, MACD_12_26, MACD_SIGNAL_9, BBP_20, ATR_14, STOCH_K, STOCH_D, CCI_20, ALPHA_SMA_20

출력 결과 (Prediction):

Pred_Prob: 상승 확률 (분류 모델 결과)

Pred_Return: 예상 수익률 (회귀 모델 결과, 듀얼 모델 사용 시)

🔥 HOJ/SLE 엔진 ‘1회 완성 버전업’ 최종 문서
📌 목적

이번 버전업은 다시 두 번 세 번 작업하지 않도록,
데이터베이스(HOJ_DB)와 엔진(HOJ/SLE)의 구조를 최종 완성형으로 구축하는 것이다.

이를 위해
📍 지금의 데이터셋에 없는 핵심 데이터(PER, PBR, 수급 등)
📍 향후 예측 성능에 필수적인 섹터/시장/거시지표
📍 기술지표 확장 및 엔진의 완성도 강화
모두 한 번에 넣어야 한다.

1) 현재 DB 상태 분석

(파일 분석 내용 반영)

● 구성

기본 OHLCV

KOSPI 수익률 2종

SMA/RSI/MACD/ATR 등 기술지표 18개

총 약 30개 수준의 “가격 기반” 데이터

● 문제점

저평가/고평가 판단 불가 (PER, PBR 없음)

세력 흐름 감지 불가 (기관·외국인 수급 없음)

섹터 / 시장 환경 판단 불가

거시지표 부재

기술지표가 단일 패턴 중심(다양성 부족)

즉, 지금 구조는
차트(기술적 분석) 기반 엔진 수준이며
실전 매매를 위한 “수급 + 가치 + 섹터” 요소가 빠져있다.

이 구조로는
→ 상승 확률 예측은 되지만
→ 폭발적 상승 종목을 골라내는 능력은 한계가 있다.

2) 추가해야 할 ‘핵심 컬럼’ 전체 목록 (최종)

아래 목록을 모두 넣으면
향후 1~2년간 추가 업그레이드 없이 그대로 유지 가능하다.

✅ A. 가치지표(Valuation) – PER/PBR/EPS/BPS

필수 중의 필수. 엔진 성능 상승률 30~50% 핵심 요소.

반드시 넣을 항목

PER

PBR

EPS

BPS

ROE

시가총액

발행주식수

있으면 좋은 항목

PSR

PCR

PEG

매출/영업익/순이익 YoY

주의

PER/PBR은 “발표일 기준”으로 적용해야 함
→ 미래 데이터 참조하면 “컨닝(leakage)” 발생

왜 필수인가?

LightGBM은 저평가 + 수급 + 상승 전환 조합을 최고의 패턴으로 학습한다.

단순 기술지표 모델보다 예측 안정성이 대폭 상승한다.

✅ B. 수급(기관/외인/연기금) – 가장 중요한 요소

수급은 실제 돈의 방향성, 예측 모델의 파워를 폭발시킴.

기본 데이터

기관 순매수량

외국인 순매수량

연기금 순매수량

순매수금액 = 순매수량 × 종가

거래대금 대비 순매수 비율

파생 데이터

5일, 10일, 20일, 60일 누적 순매수

연속 매수/매도 일수

수급 방향성 변화 지표

주의

pykrx는 날짜 누락과 오류가 많아 완전하지 않음

키움/한국투자 API로 수급 데이터를 확보하는 것이 정답

✅ C. 섹터/산업 지표 – 패턴 안정성 확보의 핵심

단일 종목만 보면 가짜 신호가 많은데
섹터는 장세를 결정하는 기준이다.

넣어야 할 항목

섹터 일일 수익률

섹터 평균 PER/PBR

섹터 거래대금

섹터 모멘텀(상위/하위 랭킹)

Industry Code (대분류/중분류)

효과

테마 장세, 로테이션 장세 감지

개별 종목의 “상대 강도” 정확도 상승

거짓 상승 신호 제거

✅ D. 시장/거시 환경 지표(Macro) – 트렌드 노이즈 제거

기술지표 단독 예측의 가장 큰 약점이 “환경을 모른다”는 것.

넣으면 좋은 항목

KOSDAQ 지수

ETF(KODEX200 등) 수익률

USD/KRW 환율

WTI/브렌트 유가

미국 금리(5년·10년)

VIX 지수

이유

환율 급등, 유가 급등, 금리 인상 → 기술적 패턴 무력화

매크로 포함하면 잘못된 매수 신호가 크게 줄어든다

✅ E. 기술지표 확장 – LightGBM 최적화

현재 18개 기술지표 외에 아래 추가하면 더욱 강력해짐.

추가 추천

MACD Histogram

TEMA (Triple EMA)

WMA (가중 이동평균)

RSI 방향성(RSI diff)

VROC (거래량 ROC)

캔들 구조(body %, shadow ratio)

Keltner Channel

이유

LightGBM은 다양한 각도에서 본 패턴을 조합해 상승 확률을 찾는 구조

기술지표 다양성을 늘려주면 모델이 비약적으로 똑똑해짐

3) 데이터 수집 가능 여부 (키움 기준)
✔ 가능한 것

주가 (일봉/분봉)

거래량

부분적 수급

현재 시점 재무정보(PER/PBR 등)

⚠ 불확실/제한되는 것

2015~현재까지의 전 기간 일별 수급

2015~현재까지의 과거 PER/PBR (발표일 기반 데이터)

키움만으로는 다음 두 개가 완전하지 않을 수 있음:

과거 재무/밸류 데이터

과거 수급 전체

따라서 완전체를 만들려면
📌 키움 + 한국투자 API + 공시 데이터 + 일부 외부 API
병합 전략이 가장 현실적이다.

4) 버전업 시 반드시 지켜야 할 병합(Merge) 규칙
① 병합방식

Left Join 필수

기존 HOJ_DB(=Left)를 절대 손상시키면 안 됨

② 결측치 처리

PER/PBR/재무 → ffill(직전값)

수급 → 0으로 채우기

섹터 → ffill

매크로 → ffill

기술지표는 자체 계산으로 자동 해결

③ Look-ahead Bias 절대 금지

미래 PER/PBR 사용 금지

실적 발표일 기준으로 값 고정

한국투자/키움 API가 대부분 처리해줌

5) 최종 HOJ_DB 스키마 (이번 버전업 완성 조건)
● 가격 기반 (기존)

OHLCV + 기술지표(18+α)

● 가치지표(신규)

PER, PBR, EPS, BPS, ROE, 시총, 발행주식수 …

● 수급(신규)

기관/외국인/연기금 순매수, 누적수급, 비율 …

● 섹터(신규)

섹터 수익률/평균 PER/PBR/거래대금 …

● 시장/거시(신규)

KOSDAQ, 환율, 금리, 유가, VIX …

● 기술지표 확장(신규)

TEMA/WMA/캔들 ratio/MACD hist …

이 총합이
150~200개 feature 규모의 완전한 LightGBM 입력셋이 된다.

이 상태면
📍 엔진 성능
📍 예측 안정성
📍 Top10 품질
📍 실전 수익률
모두 완성된다.

6) 요약 – 이번 버전업에서 반드시 해야 할 핵심
✔ 수급 + 가치 + 섹터 + 매크로 + 기술지표 확장 = 완성형 엔진
✔ 키움만으로는 일부 데이터 부족 → 한국투자/외부 API 병행 추천
✔ 병합 시 Left Join + 결측치 전략으로 안전하게 통합
✔ 이번에 완전히 구성하면 2차 업그레이드는 필요 없음
