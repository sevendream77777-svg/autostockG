총정리

주식추천프로그램 데이터 설계 완성본 (6개 전체 설계본)

본 문서는 다음 방에서 곧바로 구현에 착수할 수 있도록, 개념·스키마·폴더·운영 규칙까지 모두 포함한 최종 설계안입니다. 코드 작성은 이 문서를 그대로 기준으로 합니다.

0. 전역 규칙(모든 수집기/저장공통)

타임존: Asia/Seoul, 기준 시각 = 거래일 종가(EOD) 기준.

키:

종목 일별 테이블: (date, code) 복합 PK

분기 재무: (report_date, code) 복합 PK

이벤트: (event_date, code, event_type) 복합 PK

Point-in-Time(PIT): 해당 날짜에 시장/사용자가 볼 수 있었던 값으로 고정. 재수집 시에는 asof_ts 칼럼으로 “그때의 스냅샷”을 보존(히스토리컬 스냅샷 방식).

다중 소스: source_primary, source_fallback_used (bool), source_detail 저장.

검증(QC) 공통: 결측률, 범위 체크, 급변(5σ) 알림, 시총≈종가×주식수 일관성, 거래정지/상하한가 마스크.

저장 포맷: Parquet(원천/중간/집계), HDF5(엔진 입력 Feature Set).

디렉터리 루트(윈도우→Git 경로 매핑):

실제: F:\autostockG\

문서 내 표기: /autostockG/

파티션 전략: date=YYYY-MM-DD(일별) + year=YYYY(상위) 혼용. 종목 단위 대량 I/O 최적화 위해 row-group: 50k~100k rows 권장.

1) Macro/Index Collector 설계
1.1 대상 시리즈(필수)

국내지수: KOSPI, KOSDAQ

해외/거시: SPX, NDX, VIX, DXY, US10Y, KR10Y, USDKRW, WTI, Brent
-衍生(수익률/변환): 각 시리즈 ret_1d/5d/20d, 로그수익률, level_z_252.

1.2 스키마

table: macro_daily

date (date)

kospi_close, kosdaq_close (float)

spx_close, ndx_close, vix_close, dxy_close (float)

us10y_yield, kr10y_yield (float)

usdk_rw (float) // 환율

wti_close, brent_close (float)
-衍生: *_ret_1d, *_ret_5d, *_ret_20d, *_z_252 (float, 계산 필드 → materialized view)

메타: asof_ts (ts), source_primary (str), source_fallback_used (bool), source_detail (str)

1.3 소스·페일오버

1차: 공식/권위 API(국/해외), 거래소/중앙은행 등

2차: 보조 데이터벤더

3차: 합법 공개 웹 페이지 크롤러

KR10Y는 한국은행 API 사용(일 단위), 환율은 공개 API/보조 소스 병행.

1.4 수집·정합

스케줄: 거래일 18:30 KST 이후 EOD 수집(지수/환율/금리의 종가 데이터).

결측 처리: 당일 결측은 미기록, 다음 배치에서 보강. 과거 결측 발생 시 백필 배치 별도 운영.

거래일 캘린더: 한국 거래일 기준. 해외 자산은 한국 기준 날짜로 스냅(UTC→KST 변환, 날짜 충돌 시 최근 영업일로 스냅).

1.5 저장

Parquet 경로: /autostockG/MODELENGINE/RAW/EXTERNAL/MACRO/year=YYYY/part-*.parquet

뷰: macro_daily_mv (수익률·표준화衍生 컬럼 포함, 머티리얼라이즈드)

2) Sector(업종) Collector 설계
2.1 목적

섹터 메타(티커→섹터 매핑) 관리

섹터 일별 집계: 시총가중 평균/수익률/회전율/섹터 RS 등

table: sector_meta

메타: asof_ts, source_primary, source_fallback_used, source_detail

2.3 집계 규칙

가중치: 시총가중(기본), 필요 시 자유유통시총가중 옵션 추가.

섹터 수익률: 섹터 구성종목 close 기반 시총가중 평균 후 수익률 계산.

RS(Relative Strength): 섹터 20/60일 수익률을 KOSPI 동기간과 비교.

변동 구성(편입/편출): sector_meta의 히스토리로 재현.

2.4 소스·페일오버

1차: 거래소/브로커 메타

2차: 보조 웹(업종코드 표/섹터 분류 표준)

섹터명/코드 표준화 테이블 유지(사전에 수동 검수 1회).

2.5 저장

Parquet:

메타 /.../META/sector_meta.parquet (스냅샷 전체교체)

일별 /.../DERIVED/SECTOR/year=YYYY/part-*.parquet

revision_flag (bool), rev_version(int) // 정정공시 반영 버전

메타: asof_ts, source_primary, source_fallback_used, source_detail

3.3 정정공시/버저닝

동일 (report_date, code) 다중 버전 허용 → rev_version 증가.

엔진 기본은 최신 버전 사용하되, 백테스트용 PIT 스냅샷 선택 기능 제공.

연결/개별 기준은 연결 우선, 미존재 시 개별.

3.4 소스·페일오버

1차: 전문 재무 데이터(분기)

2차: 공시/요약(법적 데이터)

3차: 보조 포털(표준화 필요)

3.5 저장

Parquet: /.../EXTERNAL/FINANCE/year=YYYY/part-*.parquet

조회 뷰: finance_quarterly_latest (각 (report_date, code)의 최신 rev_version)

4) Event Collector 설계
4.1 대상 이벤트

ex_div_date(배당락), pay_date(배당지급), earnings_date(실적발표), rights_issue_event(권리/증자/감자/분할), mna_event(M&A/합병/분할)

4.2 스키마

table: corporate_event

event_date (date), code (str), event_type (enum: EXDIV, PAYDIV, EARNINGS, RIGHTS, MNA, HALT, RESUME …)

value_1 (str/float, 예: 배당금/비율), value_2 (str/float), note (str)

pit_effective_from (date) // 시장이 인지한 시점

메타: asof_ts, source_primary, source_fallback_used, source_detail

PK: (event_date, code, event_type)

4.3 중복/상충 제거

우선순위 규칙: 공시 > 전문 데이터 > 포털

동일 (date, code, type) 중복은 value 우선순위 규칙으로 병합.

상충 시 conflict_flag = true, note에 출처 및 차이 기록.

4.4 PIT 처리

pit_effective_from 사용: 시장 인지 시점 기록(뉴스/공시 시차 반영).

백테스트 시 “발표 이전에는 모름” 제약을 보장.

4.5 저장

Parquet: /.../EXTERNAL/EVENTS/year=YYYY/type=EVENTTYPE/part-*.parquet

5) Parquet/H5 저장 구조 설계
5.1 디렉터리 트리(예시)
/autostockG/
  MODELENGINE/
    RAW/
      INSTRUMENT/          # 종목 일별 원천(OHLCV/밸류/수급) 통합
        year=2015/part-*.parquet

5.2 파일 단위/파티션

일별 병합 스냅샷: INSTRUMENT는 날짜 파티션보다 연도 파티션이 I/O 효율적.

이벤트/매크로/재무: 연도 파티션 + 타입 보조 파티션.

Row Group: 50k~100k. 압축 snappy.

5.3 스키마 고정/버전

schema_version: 문자열(예: v1.0.0)을 모든 Parquet 메타에 주입.

열 추가 시 Minor, 타입 변경 시 Major 올림. 다운스트림에서 스키마 핸드셰이크.

5.4 H5(엔진 입력)

파일명: final_feature_set_YYYYMMDD.h5

구조:

meta/date_index → 날짜 배열

meta/code_index → 종목코드 배열

data/features → float32 [N_date, N_code, N_feat] 3D 블록(결측은 NaN)

data/mask → uint8 동일 shape(1=유효), 거래정지/데이터부족 마스크

Chunking: (1, 256, all_feat) 또는 (date, code) 축 기준 실험 후 고정.

무결성: sha256 체크섬 파일 동반 저장.

6) Feature Set 300~600 자동 생성 엔진 설계
6.1 입력 소스

6.2 공통 규칙

표준화: z-score(252일 롤링), min-max는 비권장.

리스크가중: 필요 시 변동성/유동성 가중 스케일러 별도 제공.
