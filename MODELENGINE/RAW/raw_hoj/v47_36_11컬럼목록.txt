[PART 0] 운영 규칙 (Operational Rules & ETL)
* 이 규칙들은 DB 스키마에는 저장하지 않으며,
  데이터 로딩/전처리/모델링 과정에서 반드시 적용해야 하는 필수 절차임.
====================================================================

1. Feature Layer 자동 생성 (Daily ETL 단계)
   * 아래 파생 변수들은 DB에 저장하지 않고, 매일 로드 시 자동 생성하여 모델에 주입한다.
   * 목적: 성능 향상, 시계열 구조 안정화, 데이터 노이즈 감소.
     - change_rate (등락률)
       = close / prev_close - 1
     - vol_change_rate (거래량 변화율)
       = volume / prev_volume - 1
     - high_low_spread (고저폭 비율)
       = (high - low) / close
     - close_loc (캔들 위치: 종가의 상대적 위치)
       = (close - low) / (high - low)

2. 기관 수급 데이터 해석 규칙
   * inst_net_amt 는 nps/tust/dealer 의 단순 합이 절대 아님.
   * 정의:
       inst_net_amt =
           기관 전체(투신, 연기금, 금융투자, 보험, 은행, 기타법인, 사모펀드 등)
           순매수 금액을 모두 포함한 값.
   * 모델 적용 시:
       → inst_net_amt = “기관 전체 흐름”
       → nps/tust/dealer = “기관 세부 성격” 분석용

3. earnings_date 사용 규칙 (미래정보 누수 방지)
   * earnings_date 는 “예정일”이며 실제 공시일과 다를 수 있음.
   * 정확한 재무제표 반영 및 주가 매핑 기준은 announce_date.
   * ML 모델에서 미래 데이터 누수를 방지하려면:
       → earnings_date는 이벤트 리스크 필터용
       → 재무 반영일은 announce_date 로 통일

4. adj_factor 사용 규칙
   * 목적: 분할/병합/배당락 등 가격 보정 발생 시 검증 및 adjust_close 생성용.
   * adj_factor 자체를 모델에 넣으면 위험:
       - 가격 이벤트 누수
       - 분기별 점프로 인해 모델 왜곡
   * 결론: ML Feature로 절대 사용 금지.
