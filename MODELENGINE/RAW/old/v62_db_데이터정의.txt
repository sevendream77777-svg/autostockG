1. 전체 시스템 구조 개요
1.1 목적

10~20년 단위의 모든 종목 가격·수급·거시·섹터·재무·이벤트 정보를 정확한 PIT(과거 시점 일관성) 기준으로 저장

엔진이 자동으로 300~600개 피처를 생성할 수 있는 깨끗한 원천 DB 구축

최종적으로 “하루 단위/시간 단위”로 Top10 추천을 안정적으로 생성하는 Daily Recommender Pipeline 운영

1.2 전체 파이프라인 구조
[Collector] → [RAW Parquet Cache] → [PIT 조정] → [Master Table] → 
[Auto Feature Generator 300~600] → [H5 Feature Snapshot] →
[Training Engine HOJ/SLE] → [JSON 모델정보 + 예측결과] → [UI + 알림 시스템]

3. PIT (Point-in-time) 아키텍처
3.1 PIT 핵심 원칙

어떠한 경우도 “미래 정보가 과거에 보이는 것”을 허용하지 않는다.

PIT join default:

left_df.join(right_df, on='code', how='left')
→ right_df는 pit_effective_from 기준으로 과거 데이터만 FFill 허용
→ 미래 데이터는 절대 조인 금지

3.2 PIT 테이블 종류

가격 PIT → 조정 전/후 모두

재무 PIT → 발표일 기준

섹터 PIT → 유효기간 테이블

이벤트 PIT → 이벤트일, 선언일 이중 저장
