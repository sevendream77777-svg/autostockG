# 병렬 수집 가이드 (하루 내 대량 수집)

## 빠른 시작

### 1. 전체 종목 리스트 가져오기
```bash
python get_all_stocks.py --output stocks.txt
```

### 2. 전체 기간 수집 (병렬)
```bash
python run_raw_v52_parallel.py \
  --codes stocks.txt \
  --date-range 20150102:20251205 \
  --workers 500 \
  --no-debug
```

## 파라미터 설명

- `--codes`: 종목코드 파일 경로 또는 콤마 구분 리스트
- `--date-range`: 날짜 범위 (START:END)
- `--workers`: 워커 프로세스 수 (기본: CPU*10, 최대 500)
- `--chunk-size`: 청크 크기 (기본: 10)
- `--out-dir`: 결과 저장 폴더
- `--no-debug`: 디버그 JSON 저장 안 함

## 성능 최적화

### 워커 수 조정
- **100개 워커**: 약 33일 소요
- **200개 워커**: 약 16.5일 소요
- **500개 워커**: 약 6.6일 소요
- **1000개 워커**: 약 3.3일 소요 (API 제한 고려 필요)

### 하루 내 수집을 위한 권장 설정
```bash
# 최대 워커 사용 (하루 내 수집 목표)
python run_raw_v52_parallel.py \
  --codes stocks.txt \
  --date-range 20150102:20251205 \
  --workers 1000 \
  --chunk-size 5 \
  --no-debug
```

## 주의사항

1. **API 제한**
   - DART: 10,000건/일
   - ECOS: 30,000건/일
   - 대량 수집 시 제한 초과 가능

2. **메모리 사용량**
   - 워커 수가 많을수록 메모리 사용량 증가
   - 시스템 리소스 모니터링 필요

3. **네트워크 대역폭**
   - 동시 요청이 많을수록 네트워크 부하 증가
   - 안정적인 인터넷 연결 필요

## 예상 소요 시간

- **2,772종목 × 2,750일 = 7,623,000건**
- **500개 워커**: 약 6.6일
- **1000개 워커**: 약 3.3일
- **2000개 워커**: 약 1.6일 (API 제한 고려 필요)

## 문제 해결

### 메모리 부족
- 워커 수 감소 (`--workers 200`)
- 청크 크기 증가 (`--chunk-size 20`)

### API 제한 초과
- 워커 수 감소
- 날짜 범위를 나눠서 수집

### 속도가 느림
- 워커 수 증가
- 청크 크기 감소 (`--chunk-size 5`)
